Project Name:
Task Management System – Proof of Concept (PoC)

Objective:
Build a backend system using FastAPI to manage personal or team tasks.
Supports full CRUD operations, along with task status, priority, deadlines, and optional user assignment.

Input (Task Fields via API):
- title: string (e.g., "Submit report")
- description: string (e.g., "Weekly report for project A")
- status: string (Allowed: "Pending", "In Progress", "Completed")
- priority: string (Allowed: "Low", "Medium", "High")
- deadline: ISO datetime string (e.g., "2025-07-10T18:00:00")
- assigned_to: string (optional, e.g., "john_doe")

Output (API response):
- JSON object with full task details, including:
  - id: auto-generated unique ID
  - title, description, status, priority, deadline
  - created_at: timestamp
  - assigned_to: if applicable

Users:
- Single-user by default (no login)

Core Features (CRUD):
- Create Task        [POST /tasks/]
- Get All Tasks      [GET /tasks/]
- Get Task by ID     [GET /tasks/{task_id}]
- Update Task        [PUT /tasks/{task_id}]
- Delete Task        [DELETE /tasks/{task_id}]

Business Rules & Logic:
- status must be one of: Pending, In Progress, Completed
- priority must be one of: Low, Medium, High
- deadline must be a valid future datetime
- Log warning if a task is overdue during GET

Filtering Support:
- Filter by status:     GET /tasks/?status=Pending
- Filter by priority:   GET /tasks/?priority=High
- Filter by assigned_to: GET /tasks/?assigned_to=john_doe

Tech Stack:
- FastAPI for API development
- Pydantic for data validation
- JSON file for data persistence (e.g., tasks.json)
- Logging for tracking events (e.g., task created, overdue)
- Postman for API testing
- Custom exceptions for clean error responses

Goal:
Demonstrate clean API development with structured codebase including models, logging, decorators, and exception handling.
